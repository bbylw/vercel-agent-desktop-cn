---
title: 会话与追踪
description: 把一串命令和它们各自的快照留在同一段历史里，供事后复盘和取证。
---

一次任务往往由几十条命令组成。默认情况下每条命令都在独立进程里运行、打印一个信封然后退出，
彼此之间不留状态。会话和追踪负责把这段过程变成可以回看的东西。

## 会话

```bash
agent-desktop session          # 会话状态与用法
agent-desktop session --help   # 单条命令的参数
```

会话的用途是把一段操作历史和它的快照、游标叠层放在一起管理：
`session` 管记录，`trace` 管产物，`cursor-overlay` 管把指针位置画出来以便人眼核对。

## 追踪

```bash
agent-desktop trace
```

追踪把命令序列和每一步的读数留下来。它的价值出现在两个时刻：智能体做出了一件你没预料到的事，
需要知道它当时看到的是哪棵树；以及同一段流程需要复放以确认它是稳定的。

## 批量执行

```bash
agent-desktop batch
```

`batch` 把多条命令放在一次调用里提交，省掉逐条起进程的开销。适合已经确定好的动作序列——
探索阶段仍然应该一条条来，因为每一步都要读上一步的结果才能决定下一步。

<Aside type="caution" title="追踪产物里含桌面内容">
  快照、剪贴板读取、截图、命令输出和调试产物都可能包含桌面上的私密内容。
  不要把追踪产物放进公开日志或者上传。见[隐私与数据处理](/privacy/)。
</Aside>

## 无头与有头

每次 CLI 调用都在独立进程中运行。无头调用依然禁止激活前台窗口和合成输入；
只有全局 `--headed` 才允许物理输入。这个边界影响的是「你能观察到什么」：
有头模式下的前台切换会改变界面本身，追踪里读到的树也随之不同。
